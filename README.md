# Agent_Newton

A multi-agent intelligent tutoring system built around a **shared learner-state
layer**, with a simulated-learner harness for running controlled, reproducible
comparisons between architectural variants.

The subject matter is pluggable. Two domains ship: `calculus` (single-variable)
and `toy_algebra`, a small reference domain used as a fast test fixture.

## What it does

A tutoring session runs as a loop:

1. The **planner** selects the next concept and item.
2. The **simulated learner** (or a human, in the demo) produces a step.
3. The **verifier** checks that step symbolically — no model involved.
4. On an incorrect step, the **diagnostic** agent labels the underlying
   misconception.
5. The **shared learner state** updates: per-concept mastery, a rolling error
   trace, an append-only audit record.
6. The **arbitration policy** decides whether the evidence warrants replanning.
7. The **tutor** returns a hint at a level chosen from the learner's mastery.

Agents never call one another. All coordination passes through the shared state,
which is a blackboard: each agent reads a *view* of it and writes back
observations. A test enforces that no agent-to-agent call path exists.

```bash
uv sync --dev
```

uv run pytest -q

## Run

Validate a run configuration:

```bash
uv run agent-newton config-check experiments/configs/smoke.yaml
```

Check a domain's content for internal consistency:

```bash
uv run agent-newton domain validate all
```

## Layout

| Path | Contents |
|---|---|
| `src/agent_newton/core/` | Subject-independent: state, agents, pedagogy predicates, arbitration, simulator, orchestration, evaluation |
| `src/agent_newton/domains/` | Subject matter behind five Protocols |
| `src/agent_newton/llm/` | Ollama / Anthropic / OpenAI adapters and a response cache |
| `experiments/` | Run configurations, cohort runner, analysis |
| `docs/` | Technical reference |
| `results/` | Run artifacts — manifests, metrics, figures |

`core/` never imports a concrete domain. It is generic over the Protocols in
`domains/base.py` and receives a `Domain` as a parameter. This is checked by
`tests/integration/test_domain_independence.py`, which walks every module under
`core/` and catches static, relative and dynamic imports alike.

See [docs/architecture.md](docs/architecture.md) for the component reference and
[docs/domain_interface.md](docs/domain_interface.md) for how to add a subject.

## Models

Runs default to local Ollama (`gemma4:12b`), so nothing here requires an API key.
Provider and model are set **per role**, and roles can be mixed freely:

```yaml
agents:
  tutor:      { impl: llm, provider: ollama, model: gemma4:12b }
  diagnostic: { impl: llm, provider: ollama, model: gemma4:12b }
simulator:
  surface:    llm
  surface_model: { provider: ollama, model: gpt-oss:20b }
```

Every agent also has model-free implementations — `template`, `oracle`,
`noised_oracle`, `deterministic`. These are not test doubles but run conditions:
an oracle diagnostic reads the injected label directly, a noised oracle corrupts
it at a set rate, and a fully model-free configuration runs the entire pipeline
in seconds with no inference at all.

Two configuration invariants are enforced at load rather than documented:

- **Model-lineage separation.** A configuration where the simulated learner's
  surface model shares a model family with the diagnostic agent is rejected. The
  simulated learner must not be generated by the same lineage that classifies
  it.
- **Non-degenerate parameters.** An empty mastery band, or BKT parameters where
  `guess + slip ≥ 1` (which would make evidence update backwards), are rejected.

See [docs/configuration.md](docs/configuration.md).

## Reproducibility

Every run writes a manifest carrying the git SHA, configuration hash, seeds,
resolved models, and content hashes of the domain's concept graph, misconception
catalogue and item banks.

Analysis **refuses to pool runs whose content hashes differ**. Adding a
misconception changes the diagnostic agent's label space, so accuracy figures
from before and after are not on the same scale; `assert_poolable` raises rather
than averaging them into a plausible-looking wrong number.

Content hashes are computed over canonical parsed content, so reformatting YAML
or reordering entries does not spuriously invalidate comparability.
